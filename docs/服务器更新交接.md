## 部署步骤

1. 在新的发布目录（例如 `/opt/xianyu-releases/<时间>/`）克隆仓库并检出 `codex/desktop-bridge-delivery-ai` 分支，核对交接给你的提交号。若使用备用源码包，解压后的顶层目录为 `xianyu-super-butler/`。不要覆盖现有数据，也不要直接用仓库默认 Compose 启动：它的默认端口、容器名、相对数据挂载与现有服务不一致。
2. 只读核实当前容器的实际镜像 ID、端口、挂载、运行用户、网络、环境变量、启动命令、重启策略和健康检查。把完整配置保存到权限为 `600` 的服务器本地文件，不把环境变量、Cookie、密码或令牌打印到对话中。已有环境变量和业务开关需要延续，不重置管理员密码，不擅自启用自动发货。
3. 在新发布目录从本次源码构建本地镜像，例如 `sudo docker build -t xianyu-super-butler:local-<时间> .`。Dockerfile 会构建前端并安装 Python、浏览器依赖。构建完成前保持旧服务运行。若遇到镜像源问题，先检查仓库的 Dockerfile-cn 是否适用，说明实际使用的构建方式；不能退回旧预构建镜像并声称已更新。
4. 为切换准备只包含管家应用的启动配置，保留当前外部端口 `38888:8080` 和原有绝对数据挂载路径。根据实际 inspect 结果迁移运行参数。设置 `BROWSER_COOKIE_REFRESH_ENABLED=false`。保留 `XIANYU_SIGN_ALGORITHM=md5`；HMAC-SHA1 只是未验证的实验模式，不能作为生产修复启用。桌面查询使用客户端已有 SDK，不依赖这个实验算法。
5. 检查旧容器的 `/app/static/uploads`。若有历史上传图片，先复制到独立备份目录并核对，然后准备 `/opt/xianyu/uploads`，保留已有图片；将它挂载到新容器 `/app/static/uploads`。不要先挂载空目录造成旧图片不可见。检查旧容器中的 `global_config.yml` 或其实际挂载来源，保留必要现有配置，勿盲目覆盖。
6. 镜像和配置就绪后进入短暂停机切换：停掉旧容器，在所有管家写入停止后备份整个数据目录（包含 SQLite 数据库和可能存在的 WAL/SHM 文件），以及配置和上传图片。备份存到独立目录，例如 `/opt/xianyu-deploy-backups/<时间>/`，避免放入被备份目录自身。记录旧容器和镜像 ID，保留可回滚的容器；若重命名旧容器，防止它在 Docker 重启时自动启动抢占端口。
7. 从刚构建的新镜像启动容器，继续使用 `xianyu-butler` 名称和原有数据。首次启动可能执行数据库迁移。不要同时运行两个实例连接同一账号、写入同一数据库。
8. 检查容器健康和 `http://127.0.0.1:38888/health`，确认网页静态资源可加载、原账号/商品/规则/库存仍存在。检查以下新界面：桌面客户端接入及查询开关、多参数发货模板、商品 AI 提示词、AI 固定图片规则。读取日志时先脱敏。不要发送真实买家消息、触发发货或下单来做测试。
9. 确认 `/desktop-bridge/download` 能下载新版连接工具，ZIP 包含 `bridge.py`、`app.py`、`queries.py`、`protocol.py`、`start.bat`、`requirements.txt`、`README.md` 共七个文件。同步更新后需要在 Windows 上重新下载连接工具；服务器部署不代表已验证官方客户端兼容性。
10. 报告新镜像 ID、容器状态、访问地址、备份位置和回滚方式。不要输出敏感配置。若新服务失败，停止新容器，先保留失败现场的数据副本，再恢复停机备份和旧运行配置。旧版本不能直接假定兼容已迁移的新数据库；恢复备份也会丢弃切换后新增数据，先检查并说明这部分差异。

## 本次验证与功能范围

- 本地 449 项自动化测试通过，前端类型检查和生产构建通过。
- Chromium + 模拟客户端 SDK + 本地 HTTP/SQLite 的查询往返测试通过；页面开关、状态和下载接口测试通过。
- 未在上述服务器部署，未在真实 Windows 闲鱼卖家客服版本上验证。
- 桌面模式支持 Cookie 同步及商品列表/详情、卖出订单列表/数量和订单详情查询，需要客户端开放本机调试入口及页面 MTOP SDK。
- 消息收发、自动回复、发货等其他业务仍走原服务器逻辑，不能称为全部业务接管或承诺永不出现滑块。

Windows 连接步骤见 `desktop_bridge/README.md`。远程会话同步需要 HTTPS，也可以使用文档中的本机 SSH 隧道；不要把客户端调试端口开放到公网。
