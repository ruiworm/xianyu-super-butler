# HMAC-SHA1 实验模式

项目的 H5 API 原有签名为 `MD5(token&t&34839810&data)`，通过 `sign` 参数发送。现在两个签名入口统一调用 `utils/request_signing.py`，支持通过环境变量切换算法。

在运行环境或 Docker Compose 的 `.env` 中设置：

```dotenv
XIANYU_SIGN_ALGORITHM=hmac-sha1
```

源码运行需将该变量导出到 Python 进程环境；Compose 会读取 `.env` 并传入容器。更新镜像并重新创建容器后生效，单纯重启旧的预构建镜像不会包含此修改。

实验模式明确采用以下本地约定：

- 密钥：当前请求的 token（原有调用方从 `_m_h5_tk` 取出的 token 部分）。
- 消息：原始 `token&t&34839810&data` 字符串的 UTF-8 字节，不重新序列化 JSON。
- 结果：HMAC-SHA1 的小写十六进制，仍放在 `sign` 参数。

**这是用于实验的参数约定，并非已核实的闲鱼卖家客服签名协议。** 没有证据表明现有 H5 接口接受此签名，因此预期可能出现鉴权失败。不会因签名失败自动改用另一种算法重放请求；原有的令牌续期重试逻辑不变。签名算法的切换不代表已接管官方客户端，也不能消除滑块验证或解决会话掉线。

默认仍为 `md5`。回退时设置 `XIANYU_SIGN_ALGORITHM=md5`，重新创建容器或重启源码进程。未知算法直接报配置错误；HMAC 模式缺少 token 时拒绝生成签名。程序警告不输出 token、Cookie 或签名。

本地测试仅检查算法结果、请求携带签名和旧协议兼容性，不证明真实闲鱼接口接受 HMAC-SHA1。
